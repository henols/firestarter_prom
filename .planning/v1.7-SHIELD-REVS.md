### Runtime-Guard Follow-Up Todos (out of scope for v1.7)

Per CAPS-02, when a rev physically cannot support an algorithm but firmware would still attempt it, a follow-up todo is captured for runtime-guard implementation in a later milestone. Phase 32 inventories the following gaps surfaced during §6 fill:

1. **runtime-guard:no-detect-pre-Rev2** — Rev 0 and Rev 1 lack the R41 detect divider (R41 designator does not exist in the pre-Rev 2 schematic era). Firmware cannot auto-detect these revs via ADC; fall-through is to `rev_unknown` + EEPROM `hardware_revision` byte fallback (Phase 34 substrate). No runtime guard fires — operator-side trust is the only safety. Out of scope for v1.7; runtime-guard implementation deferred to a post-v1.7 milestone once the CAPS matrix is solid.

2. **runtime-guard:rev22-r41-value-discrepancy** — Rev 2.2 schematic shows R41 = 4k7 but Anders chat (CHAT-INTEL §1, 2025-04-28) states R41 = 10k. Phase 34 ADC-band lookup may misclassify Rev 2.2 vs Rev 2.3 (both at A3, different values) until the physical R41 value on operator's Rev 2.2 board is measured (Phase 35 HUMAN-UAT follow-up #5). Out of scope for v1.7.

3. **runtime-guard:modified-rev0-rework-uninventoried** — Modified Rev 0 (operator's third board) carries hardware-bug-A/B rework (cuts + jumpers) that is not yet traced against the upstream Rev 0 schematic. Programming on this board is operator-attested only; firmware cannot detect or validate the rework. Phase 35 follow-up #4 (write full MODIFICATIONS.md) is the canonical action; downstream runtime-guard implementation is a post-v1.7 concern. Out of scope for v1.7.

4. **runtime-guard:caps-matrix-enforcement** (umbrella todo) — per REQUIREMENTS.md "Future Requirements": "Runtime algorithm-vs-rev capability guards (firmware refuses an algorithm if the bench rev physically cannot support it) — captured as a CAPS-02 follow-up todo; implement in a later milestone once CAPS matrix is solid." All four gaps above feed this umbrella todo. Implementation scope: ADC-read at boot or first handshake (Phase 34 substrate) → lookup rev capability in §6 matrix → if the requested protocol_id is not in the rev's `supported_protocol_ids` cell, refuse with a clear error. Out of scope for v1.7; recorded here as Phase 32's contribution to the CAPS-02 follow-up ledger.
