<objective>
Close the SC#3 / DB-05 BLOCKER (net safety regression) found in 66-VERIFICATION.md:
13 of 14 non-supported chips retain `algorithm=0x0B`, which `dispatch()` maps to
`configure_eprom` — a real 12V-VPP programming handler. `firestarter write AT28C04`
would drive 12V onto the WE pin (hardware-damage path) despite the chip being flagged
`adapter-required`. The `check_dispatch.py` gate cannot detect this because it only
asserts the regression direction (supported -> not_implemented) and has NO assertion
for the dangerous inverse (non-supported -> real handler), so it prints a FALSE PASS.

Apply CR-01 Option A (data-layer fix): set `proto_id = NON_DISPATCHABLE_ALGO` (0x00)
at both non-supported assignment sites in `build_db.py`. `dispatch(0x00, None)` falls
into the mem_type chain with `mt=None` and returns `ERROR` — never `configure_eprom`.
Then add the `non_supported_dispatchable` assertion to `check_dispatch.py` (CR-02) and
a CI test (IN-03) that pins the D-03 HARD invariant.

Purpose: enforce the milestone's HARD constraint "no new chip becomes programmable"
at the data layer AND prove it in CI — the entire reason Phase 66 exists.

Output: edited `build_db.py` (2 sites + 1 constant), regenerated `chip_database.json`
(14 non-supported chips now `algorithm=0`), hardened `check_dispatch.py`, new CI test,
regenerated `dispatch_baseline.json` (D-11 authorized deviation), all gates green.
