# Phase 67.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

Host-only Python work in the `firestarter_app/` submodule (DB-02 SRAM pinout
classification + DB-04 capability reporting). The threat register was authored at
PLAN time (`register_authored_at_plan_time: true`); this audit VERIFIES each declared
mitigation exists in the implemented code — it does not scan for new threats.
Implementation files were treated as read-only.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| build_db.py classification → chip_database.json | A wrong pinout/algorithm/support_status here propagates to the wire bus-config the firmware drives | Chip pinout key, support_status, unsupported_reason |
| chip_database.json → firmware (via host) | A `supported` chip with a wrong pinout would wire the RURP bus to the wrong physical pins | RURP bus config (pin/voltage routing) |
| CLI command → chip_resolver.resolve_chip | Host guard that must refuse a non-supported chip BEFORE any serial byte / wire dict | Chip name → resolved config or typed refusal |
| chip-op handler → serial_comm | The point past which a chip would actually drive RURP hardware | Programmer command bytes over serial |
