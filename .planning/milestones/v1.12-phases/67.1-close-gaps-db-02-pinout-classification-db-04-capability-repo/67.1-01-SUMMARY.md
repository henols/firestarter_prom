# Phase 67.1 Plan 01: DB-02 Pinout Classification + DB-04 Reason Strings Summary

Repaired the DB build pipeline so the 14 native-SRAM DIP chips that previously fell through `resolve_pinout_key` to wrong EPROM pinouts now resolve to correct SRAM pinouts. Also reworded the three `unsupported_reason` strings to begin with DB-04 SC#2-required status wording so the host (Plan 02) can render them verbatim.

## What Was Built

### Task 1 — DB-02 SRAM Pinout Corrections (commit `807101e`)

**Two edits in `build_db.py`, both setting `pinout_key` directly (D-02 Option B):**

**Edit 1 — `elif pin_count == 24:` branch inside fm1608 override block:**
- Fixes Group 1: DS1220(RW), FM1208, M48T02/12, M48Z02/12, ST/M48T02/12 (4 logical chip groups)
- Sets `pinout_key = "DIP24_6116"` — SRAM pinout with `rw-pin=[21]` (WE)
- Replaces incorrect `DIP24_2716` fallback (which has `vpp-pin=[21]` — 12V VPP to WE pin, wrong for SRAM)
- Evidence: DS1220 datasheet pin 21 = WE; piersfinlayson/one-rom `DIP24_6116` datasheet-verification
- Per Pitfall 6: override is inside the fm1608 block (after `proto_id` is set to 0x28), NOT via `PIN_MAP_PROTO_TO_PINOUT`

**Edit 2 — New adjacent block after fm1608 override:**
- Gate: `pin_count == 28 AND pm_idx == 0 AND proto_id == 0x28 AND type_int == 4 AND pinout_key == "DIP28_2764"`
- Fixes Group 2: DS1225(TEST)/8K, DS1230AB(TEST)/DS1230Y(TEST)/DS1230W(TEST3.3V)/32K, BQ4010YMA(TEST)/8K, BQ4011YMA(TEST)/BQ4011LYMA(TEST3.3V)/32K, W2464/W2465/8K, W24256/W24257A/32K, 6164/6264/8K, 61256/62256/32K
- Mem-size discriminator: `<= 8192` → `DIP28_JEDEC_SRAM_8K`; `> 8192` → `DIP28_28C256`
- Gate on `pinout_key == "DIP28_2764"` prevents re-routing already-correct chips (T-67.1-01 tamper mitigation)
- Evidence: `DIP28_JEDEC_SRAM_8K` pinouts.json "13 address bits for 8K"; `DIP28_28C256` rw-pin=[27] + JEDEC 62256 A14=pin1

**DB regenerated:** 744 chips, 14 pinout fields corrected (4 Group 1 + 10 Group 2).

**4 new tests in `TestSramPinoutCorrections`:**
- `test_group1_24pin_sram_gets_dip24_6116` — DS1220(RW) → DIP24_6116
- `test_group2a_8k_28pin_sram_gets_dip28_jedec_sram_8k` — 6264 → DIP28_JEDEC_SRAM_8K
- `test_group2b_32k_28pin_sram_gets_dip28_28c256` — 62256 → DIP28_28C256
- `test_no_supported_sram_on_eprom_pinout` — regression guard: no supported SRAM chip on EPROM pinout

### Task 2 — DB-04 Approach A: Reason Strings + Full Gate (commit `22940bc`)

**Three `_unsupported_reason` string rewrites in `build_db.py`:**

- **Site A** (proto 0x34, X88C64P): `"protocol not implemented: 0x34 (XICOR NovRAM serial-parallel hybrid)"`
  - Begins with "protocol not implemented:" — contains "not implemented" substring for existing test assertion
- **Site B** (adapter-required, 9 × 24-pin EEPROMs): `"adapter required: requires a dedicated DIP24 EEPROM adapter or firmware handler — socket pin 21 = WE, which the RURP DIP24_2716 pinout maps to the 12V VPP rail (hardware-damage path)"`
  - Begins with "adapter required:" with non-empty note (DB-02 SC#1)
- **Site C** (vpp-exceeds-max, M2716/M2732 family): `"VPP {x}V exceeds programmer max ({ceiling}V)"`
  - Begins with "VPP <x>V exceeds programmer max" — uses "programmer max" not "RURP ceiling" per SC#2 wording

**DB regenerated:** 744 chips, 14 non-supported chips carry new reason strings.

**3 new tests in `TestUnsupportedReasonStrings`:**
- `test_vpp_exceeds_max_reason_starts_with_exceeds_programmer_max` — M2716 → "VPP ... exceeds programmer max"
- `test_adapter_required_reason_starts_with_adapter_required` — AT28C16 → starts with "adapter required:"
- `test_protocol_not_implemented_reason_contains_not_implemented` — X88C64P → contains "protocol not implemented"
