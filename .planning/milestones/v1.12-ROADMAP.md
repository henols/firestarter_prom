# Milestone v1.12: Firmware Protocol Dispatch Hardening + Skeletons

**Status:** ✅ SHIPPED 2026-06-16
**Phases:** 62–70 (delivering set: 62, 63, 64, 65, 66, 67.1, 69, 70)
**Total Plans:** 22

## Overview

Make the **whole stack honest about what it can and cannot program**:

1. **Firmware fail-closed dispatch** — an explicit "not implemented" wire response
   (`MSG_ERR_PROTOCOL_NOT_IMPLEMENTED = 0xBB`) the host surfaces cleanly, plus
   skeleton infeasibility markers. Eliminates the silent `mem_type` fallback hazard
   where a non-zero unimplemented `protocol` + `mem_type=1` routed to `configure_eprom`
   (12V VPP on a potentially 5V-only part).
2. **Capability-honest database** — *list* (not silently drop) the DIP parallel-memory
   chips RURP cannot fully support, flagged with a `support_status` taxonomy
   (`protocol-not-implemented` / `adapter-required` / `vpp-exceeds-max`) the host
   reports clearly via `info` and refuses (in-host, pre-serial) on `write`/`read`/`verify`.

Framework + honest reporting only; **no new chips became programmable**. First
firmware-touching milestone since v1.10. Dual-repo lockstep wire change; provable on the
native dispatch harness + host pytest (no bench required to close).

> **Scope note:** ROADMAP headed this milestone as "Phases 62–68." In execution the shape
