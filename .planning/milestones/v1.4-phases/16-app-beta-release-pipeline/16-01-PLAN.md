## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator → GitHub Actions (`workflow_dispatch.inputs.beta_version`) | Operator supplies an arbitrary string that flows into the `BETA_VERSION` env consumed by `update_version.py`. Untrusted-ish — write-scoped collaborators only, but still input validation territory. |
| `beta-release.yml` job → `secrets.PERSONAL_ACCESS_TOKEN` | The PAT is exposed to the Release step's env. Same scope as `release.yml`'s usage today. |
| `beta-release.yml` (auto-commit) → `beta` branch | Default `GITHUB_TOKEN` push; GitHub's recursion guard prevents re-trigger. |
| GitHub Release (`prerelease: true`) → PyPI (via `publish.yml`) | A successfully-created GH Release publishes a wheel/sdist to PyPI. PyPI immutability prevents version overwrite. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-01 | Tampering | `workflow_dispatch.inputs.beta_version` flowing into version-file write | mitigate | Phase 15's `update_version.py` validates `BETA_VERSION` against `FIRMWARE_VERSION_RE` (`^[0-9]+\.[0-9]+\.[0-9]+(b\|rc)?[0-9]*$`) BEFORE opening any file. Phase 16 inherits this validation by invoking the unmodified script. No shell interpolation of the input occurs in beta-release.yml (it flows only through the `env:` mapping). |
| T-16-02 | Denial of Service | Auto-commit step re-triggering `beta-release.yml` infinitely | mitigate | Default `GITHUB_TOKEN` on Checkout (no `token:` override) — GitHub's documented recursion guard prevents GITHUB_TOKEN-authenticated pushes from re-firing push-event workflows. Pattern proven by `release.yml` running today without looping. RESEARCH.md Finding 4 + Pitfall 1. |
| T-16-03 | Elevation of Privilege | Unauthorized `workflow_dispatch` invocation of beta-release.yml | accept | GitHub Actions `workflow_dispatch` is restricted to collaborators with write access on the repo. | T-16-04 | Tampering | PyPI version collision (e.g. publishing `3.1.0b1` twice) | mitigate | PyPI is immutable — duplicate version uploads return HTTP 400 and fail the publish step. Operator procedure (Phase 15 LOCKSTEP-PROCEDURE.md) documents collision avoidance. No code change in Phase 16. |
| T-16-05 | Information Disclosure | `PERSONAL_ACCESS_TOKEN` leakage via workflow logs | accept | Standard GitHub Actions secret masking. Same exposure surface as `release.yml`. ASVS V4 applies; not a Phase 16-introduced risk. |
| T-16-06 | Spoofing | Branch-protection bypass: someone force-pushes to `beta` bypassing review and ships a malformed beta to PyPI | mitigate | Inline CI gates (catalog validity + codegen drift + pytest) run BEFORE the version bump.
