Format: a "Protocol overrides" labelled paragraph (NOT a new subsection — keep section depth flat). Use the same prose density as the "Known protocols" line above it.

The paragraph must include:

1. A title-like label `Protocol overrides:` (bold or italic — match the style of "Known protocols" if it uses any emphasis; current file has plain text, so plain text is fine).

2. The override location: `build_db.py` applies an inline conditional after deriving `_etype` and before constructing `chip_entry`.

3. The 3-predicate condition, named in prose: pinout `DIP28_2764`, algorithm `0x07` (EPROM_STD), electrical type `Flash/EEPROM`.

4. The override action: such chips have their algorithm field flipped to `0x0D` (EEPROM_POLL) so firmware dispatch reaches `configure_eeprom28c` instead of `configure_eprom`.

5. The why: on the `DIP28_2764` pinout, socket pin 1 maps to the VPP regulator output line; `configure_eprom` asserts `P1_VPP_ENABLE` (12V) on every write pulse. On 28C-family 5V EEPROMs, physical pin 1 is the A14 address line — not VPP — so 12V on pin 1 is a hardware-damage path. `configure_eeprom28c` is purely 5V VCC with no VPP regulator engagement.

6. The scope: ~23 chips across ATMEL (AT28C/BV family), MICROCHIP memory (28C/28LV family), NEC (UPD28C family), ST (M28256), XICOR (X28C family), and EXEL (XLE2865A). 7 chips remain on the 0x07 path because they are genuine UV-EPROMs on DIP28_27512 or DIP28_27256 pinouts (W27C512, SST27SF512, SST27VF512, W27C257, W27E257, SST27SF256, SST27VF256) and DO need 12V VPP on pin 1.

7. Pointer to the audit: see `WARNING-5` in `.planning/v1.0-MILESTONE-AUDIT.md` and the phase folder `.planning/phases/13-close-gap-warning-5-at28c256-64-5v-eeprom-override-12v-on-we/`.

8. Regression guard pointer: `tools/check_dispatch.py` asserts no chip with `pinout=DIP28_2764 AND electrical.type=Flash/EEPROM` routes to `configure_eprom`.
