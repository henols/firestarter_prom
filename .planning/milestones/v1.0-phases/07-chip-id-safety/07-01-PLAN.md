<objective>
Add chip ID validation to flash_intel.cpp: a new flash_intel_check_chip_id() function that reads the Intel 28F manufacturer/device ID using the 0x90 autoselect command, validates against handle->chip_id, and dispatches it from both CMD_CHECK_CHIP_ID and flash_intel_write_init().

Purpose: Phase 05 created the Intel flash handler but omitted chip ID validation (REQ-SAF-02). Intel 28F chips support an autoselect command (write 0x90 to any address) that makes the device expose manufacturer ID at address 0x0000 and device ID at address 0x0001. This must be checked before any write when handle->chip_id > 0.

Reference: flash3_check_chip_id_execute() in flash_type_3.cpp uses flash3_get_chip_id() which does the AMD 0x90 autoselect (same sequence, happens to work on Intel 28F too). Intel uses the same 0x90 read-ID command.

Output: Targeted additions to flash_intel.cpp only — new function + two call sites.
</objective>

**Step 4** — Add the `flash_intel_check_chip_id()` implementation at the bottom of the file, before the closing of `flash_intel_poll_sr()`:

```c
void flash_intel_check_chip_id(firestarter_handle_t* handle) {
    handle->firestarter_set_data(handle, 0, 0x90);  // enter autoselect
    uint16_t chip_id = handle->firestarter_get_data(handle, 0x0000) << 8;
    chip_id |= handle->firestarter_get_data(handle, 0x0001);
    handle->firestarter_set_data(handle, 0, 0xFF);  // exit autoselect
    if (chip_id != handle->chip_id) {
        int response_code = is_flag_set(FLAG_FORCE) ? RESPONSE_CODE_WARNING : RESPONSE_CODE_ERROR;
        firestarter_response_format(response_code, "Chip ID %#04x dont match expected ID %#04x", chip_id, handle->chip_id);
    }
}
```
