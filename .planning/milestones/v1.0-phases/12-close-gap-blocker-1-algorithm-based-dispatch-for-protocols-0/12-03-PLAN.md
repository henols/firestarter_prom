<objective>
Replace the brittle `electrical.type` substring branch in
`firestarter_app/firestarter/database.py:_map_data` (current lines 371-377)
with an explicit algorithm-driven lookup table, per CONTEXT.md D3. This is
the Python defense-in-depth fix described in D1: even if a future firmware
rollback re-introduces mem_type dispatch, the wire-level `type` field will
match the protocol's intended handler.

Purpose: today the substring branch tags any electrically-erasable chip as
`mem_type = 2` (the orphan FLASH_TYPE_2) and any SRAM chip as `mem_type = 1`
(because the `"SRAM"` branch is unreachable — `build_db.py` never emits
"SRAM"; that fix is in Plan 04). After Plan 03 lands, every chip with a known
algorithm sends a wire-protocol `type` value that matches the firmware's
fallback expectations for that protocol (per D3 table) — even though the
post-Plan-02 firmware dispatches on `algorithm` before consulting `type`.

<interfaces>
Wire-protocol contract — `convert_to_programmer` emits `data["type"] = determined_type`
and `data["algorithm"] = protocol_id`. The firmware `json_parser.c:get_type` and
`get_algorithm` populate `handle->mem_type` and `handle->protocol` respectively.
The post-Plan-02 firmware dispatches on `handle->protocol` first; `handle->mem_type`
is the fallback only. The job of this plan is to make `determined_type` agree
with what the firmware would do if it fell back to mem_type — i.e. consistent,
defensive, and correct.

D3 algorithm→mem_type table (locked in CONTEXT.md, must be implemented exactly):

  | algorithm | mem_type | meaning                                            |
  |-----------|----------|----------------------------------------------------|
  | 0x05      | 5        | TYPE_FLASH_TYPE_4                                  |
  | 0x06      | 3        | TYPE_FLASH_TYPE_3                                  |
  | 0x07      | 1        | TYPE_EPROM                                         |
  | 0x08      | 1        | TYPE_EPROM                                         |
  | 0x0B      | 1        | TYPE_EPROM                                         |
  | 0x0D      | 1        | TYPE_EPROM (firmware dispatches on protocol prefix)|
  | 0x0E      | 4        | TYPE_SRAM                                          |
  | 0x10      | 1        | TYPE_EPROM (firmware dispatches on protocol prefix)|
  | 0x27      | 4        | TYPE_SRAM                                          |
  | 0x28      | 4        | TYPE_SRAM                                          |
  | 0x29      | 4        | TYPE_SRAM                                          |
  | 0x35      | 5        | TYPE_FLASH_TYPE_4                                  |
  | 0x39      | 5        | TYPE_FLASH_TYPE_4 (RESEARCH.md A1 — 0 DB chips)    |

Fallback: when `algorithm == 0` or absent, retain legacy substring on `electrical.type`:
"Flash" → 2, "SRAM" → 4, else → 1. This branch will not be hit by any chip in the
regenerated DB after Plan 04 lands but is preserved for user-override DBs.
</interfaces>
