<objective>
Close BLOCKER-2 at the database-pipeline layer (D4) and prove the full
Phase 12 dispatch is correct end-to-end by regenerating the DB and rerunning
the regression scan from Plan 01.

Today, `firestarter_app/tools/build_db.py` line 214 emits
`"Flash/EEPROM"` for any chip with `flags & 0x10` and `"UV-EPROM"` otherwise.
SRAM chips never receive a `"SRAM"` electrical.type — making the
`elif "SRAM" in type_str:` branch in `_map_data` permanently unreachable and
mislabeling SRAM parts in the CLI as "UV-EPROM". Per CONTEXT.md D4, this
plan adds an explicit `proto_id in {0x0E, 0x27, 0x28, 0x29}` check that
emits `"SRAM"` before the existing `flags & 0x10` fallback runs.

Purpose: complete BLOCKER-2 fix at the data layer (Plans 02 and 03 already
closed it at the firmware and host dispatch layers respectively). Also serves
as the phase-end regression checkpoint: after this plan lands and the DB is
regenerated, `check_dispatch.py` must still PASS, AND the regenerated DB
must contain exactly 52 SRAM-tagged chips (matching the BLOCKER-2 audit
count from CONTEXT.md and RESEARCH.md).

  the `chip_entry = {` dict construction (line 211); `chip_entry`'s
  `electrical.type` is set from the new `_etype` local.
- `firestarter_app/firestarter/data/minipro_complete_db.json`: regenerated
  by running `python tools/build_db.py` from the `firestarter_app/` directory.

  exits 0 against the regenerated DB.
