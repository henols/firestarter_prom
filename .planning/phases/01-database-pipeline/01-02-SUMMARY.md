# Plan 01-02 Execution Summary: Fix database.py

## Objective

Fix `firestarter_app/firestarter/database.py` to read the `algorithm` field as a direct integer from the JSON (as stored by `parse_db_2.py`) and pass it through to the firmware command dict via `convert_to_programmer()`.

## Functions Modified

### `_map_data()` (line ~324)

**Before:** Used a reverse-lookup loop over `PROTOCOL_MAP` to convert the string algorithm name (e.g., `"EPROM_STD"`) back to its integer key. This was fragile — any mismatch in string casing or naming would silently produce `protocol_id = 0`.

**After:** Reads the integer directly with `programming.get("algorithm", 0)`. When `parse_db_2.py` regenerates the JSON, `algorithm` will be an integer `protocol_id` from the minipro database.

**Also added:** `vpp_mv = electrical.get("vpp_mv", 0)` after the VPP float parsing block, and `"vpp_mv": vpp_mv` in the returned `data` dict. This passes through the integer millivolt value stored directly in the JSON (set by `parse_db_2.py`), avoiding the lossy float→multiply conversion.

### `convert_to_programmer()` (line ~436)

**Before:** Built the programmer dict without an `algorithm` key at all — the firmware never received the correct algorithm value. VPP was computed as `float * 1000` (susceptible to floating-point rounding).

**After:**
- Added `"algorithm": full_eprom_data.get("protocol-id", 0)` to the programmer dict.
- Replaced VPP calculation with: `vpp_mv = full_eprom_data.get("vpp_mv") or int(full_eprom_data.get("vpp", 0) * 1000)` — prefers the stored integer millivolt value, falls back to the float conversion for backward compatibility.

## Deviations from Plan

None. All changes implemented exactly as specified.

## Verification Results

Final verification against three chip names:

| Chip | algorithm | vpp |
|------|-----------|-----|
| W27C512 | 0x07 (EPROM_STD) | 12000 mv |
| M2764A | 0x07 (EPROM_STD) | 12000 mv |
| AT28C256 | not found | — |

`AT28C256` was not found because the JSON database has not yet been regenerated by Plan 01-01 (which runs in parallel). This is expected — the code change is correct and will work correctly once the JSON is regenerated.

`PROTOCOL_MAP` was retained at module level (not removed) as it may be used by display/diagnostic code.
