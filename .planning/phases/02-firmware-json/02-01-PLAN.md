Fix json_parser.c to parse the "algorithm" field into handle->protocol and to silently skip unknown fields instead of erroring.

Purpose: The Python CLI (after Phase 01) now sends "algorithm" in every command JSON. Without this firmware change, the firmware returns "Unknown field: algorithm" and aborts. The handle struct already has `uint32_t protocol` — no struct changes needed.

Output: A corrected json_parser.c where (a) "algorithm" maps to handle->protocol, and (b) unknown keys are skipped with no error.
</objective>

<task type="auto">
  <name>Task 2: Silently skip unknown JSON fields</name>
  <files>firestarter/src/json_parser.c</files>
  <action>
In `json_parse()`, the else-branch for unrecognized keys (around line 126) currently errors:
```c
} else {
    char field_name[32];
    int len = key_token->end - key_token->start;
    snprintf(field_name, sizeof(field_name), "%.*s", len, json + key_token->start);
    firestarter_error_response_format("Unknown field: %s", field_name);
    return -1;
}
```

Replace with a silent skip:
```c
} else {
    // Unknown field — skip key + value token silently (forward-compatible)
    token_idx += 2;
}
```

The `token_idx += 2` advances past the unknown key-value pair (same as any simple scalar field). This is safe because jsmn tokenizes the entire JSON upfront, so skipping is just advancing the index.

**Note:** The `continue` at the end of the loop body is already reached from the `found = true` path, but the else-branch needs to `continue` after incrementing — or simply fall through since `continue` is not needed when token_idx has already been advanced. Verify the loop structure to ensure the token_idx advancement is correct for the unknown-field case.
