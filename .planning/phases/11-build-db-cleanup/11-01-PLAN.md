# Phase 11-01 — Database Pipeline Cleanup

## Goal

Single canonical tool `tools/build_db.py`. Delete legacy `parse_db.py`, stale
outputs, and committed XML snapshots. Update doc + comment references. No
behavior change inside the script.

## Changes (in execution order — single wave, no internal dependencies beyond
ordering)

### Step 1 — Verify rename is mechanical

Before any `git mv`, confirm the file has no self-references:

```bash
grep -n 'parse_db_2' firestarter_app/tools/parse_db_2.py
```

Expected: zero matches. If any match appears, stop and revise the plan to
update those references inside the renamed file.

### Step 2 — Rename active parser

Use `git mv` to preserve history:

```bash
cd firestarter_app
git mv tools/parse_db_2.py tools/build_db.py
```

### Step 3 — Delete legacy files

Use `git rm` so the deletions are staged correctly. From `firestarter_app/`:

```bash
git rm tools/parse_db.py
git rm tools/infoic.xml
git rm tools/infoic2.xml
git rm tools/verified.txt
git rm firestarter/data/database_generated.json
git rm firestarter/data/pin-maps.json
```

If any of these are not tracked, fall back to a bare `rm` for that one file
only and note it in the commit body.

### Step 4 — Update .gitignore

Append exactly one line to `firestarter_app/.gitignore`:

```
tools/infoic*.xml
```

Place it near the existing `tools/__pycache__/` line. The glob covers
`infoic.xml`, `infoic2.xml`, and any future `infoicN.xml` variants.

### Step 5 — Update documentation references

`firestarter_app/CLAUDE.md` — straight string replacement
`parse_db_2.py` → `build_db.py`. There are 4 occurrences (lines 11, 19, 42,
69 as of writing). Use Edit per occurrence or a single multi-edit; the
surrounding context is unique enough for each.

`firestarter_app/firestarter/database.py` — straight string replacement
`parse_db_2.py` → `build_db.py` in comments at lines 379 and 487:

- Line 379: `# Read algorithm integer directly — set by parse_db_2.py as minipro protocol_id`
- Line 487: `# Use vpp_mv directly when available (integer millivolts from parse_db_2.py)`

No other code in `database.py` should change.

### Step 6 — Verify (goal-backward)

Run each check; all must pass before committing:

1. **File set is exactly what we expect:**
   ```bash
   cd firestarter_app
   git ls-files tools/
   ```
   Expected: `tools/build_db.py` and `tools/pin-layouts.odt` (and nothing
   matching `parse_db*`, `infoic*`, or `verified.txt`).

2. **The renamed script runs against upstream:**
   ```bash
   cd firestarter_app
   python tools/build_db.py
   ```
   Expected: completes successfully and writes
   `firestarter/data/minipro_complete_db.json`. (Requires network access to
   gitlab.com for the upstream XML fetch.)

3. **Byte-identity of generated DB (optional but recommended):**
   Before Step 2 (rename), capture a baseline:
   ```bash
   cd firestarter_app
   cp firestarter/data/minipro_complete_db.json /tmp/minipro_complete_db.before.json
   ```
   After Step 6.2, diff:
   ```bash
   diff /tmp/minipro_complete_db.before.json firestarter_app/firestarter/data/minipro_complete_db.json
   ```
   Expected: no diff. If the files differ, abort — upstream may have changed
   between runs (acceptable) but in that case re-run `parse_db_2.py` from the
   reflog'd version against current upstream to compare. The rename itself
   must not introduce any diff.

4. **No stale references remain:**
   ```bash
   grep -rn 'parse_db_2\|parse_db\.py' firestarter_app/ --exclude-dir=.git --exclude-dir=__pycache__
   ```
   Expected: no matches.

5. **Clean tree, no resurrected XML:**
   ```bash
   cd firestarter_app
   git status
   ```
   Expected: changes staged from Steps 2–5, nothing else. In particular, no
   untracked `infoic*.xml` (the `.gitignore` addition covers them if Step 6.2
   re-fetched them — but Step 6.2 fetches in-memory only, so they shouldn't
   appear at all).

### Step 7 — Commit

Single atomic commit. Suggested message:

```
refactor(phase-11): rename parse_db_2 to build_db, remove legacy parser and committed XML

- git mv tools/parse_db_2.py -> tools/build_db.py (preserves history)
- Remove legacy parse_db.py and its inputs/outputs:
  tools/infoic.xml, tools/infoic2.xml, tools/verified.txt,
  firestarter/data/database_generated.json,
  firestarter/data/pin-maps.json
- .gitignore: add tools/infoic*.xml to prevent recommit
- Update parse_db_2.py -> build_db.py references in
  CLAUDE.md (4 occurrences) and database.py comments (lines 379, 487)

REQ-DB-05. No behavior change inside the script.
```

## Known issues (out of scope)

The `verified` field in `minipro_complete_db.json` is no longer populated
(legacy `parse_db.py` sourced it from `verified.txt`; `build_db.py` does not).
This means `get_eproms(verified=True)` silently returns nothing. Pre-existing
bug, not introduced by this phase. Track separately.

## Success Criteria

All five verification checks in Step 6 pass. Single commit landed. History
preserved for `build_db.py` (verify with `git log --follow tools/build_db.py`).
