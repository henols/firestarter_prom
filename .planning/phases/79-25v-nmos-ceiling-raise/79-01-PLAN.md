<objective>
HARDWARE GATE (NMOS-01) — the FIRST step of Phase 79 and a hard precondition for every subsequent
code change. Confirm, by operator multimeter on a chip-OUT dry-run, that the on-bench shield can
safely produce >= 25V VPP at the socket VPP pin BEFORE `RURP_VPP_CEILING_MV` is raised 22000->25000.

The 22V software ceiling reflects a rail/calibration limit, and the firmware does NO runtime VPP
ceiling enforcement (`eprom_check_vpp` only checks measured-vs-requested +/- tolerance; confirmed by
source grep in 79-RESEARCH.md Q3). Therefore nothing in software stops a write if the rail is
miscalibrated — the physical measurement is the only thing that proves a 25V chip can be driven
safely. This plan must NOT proceed to the code change; it only clears (or fails) the gate and records
the evidence.

Purpose: NMOS-01 — record measured >= 25V VPP + silkscreen shield rev + live R1/R2 reconcile so the
Plan 02 ceiling raise is authorized on hardware grounds, not assumption.

Output: 79-01-SUMMARY.md with the full chip-OUT dry-run record and the gate verdict.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host `firestarter vpp` command → firmware VPP boost rail | the command raises the boost rail to the hardware setpoint; with a miscalibrated R1/R2 or an unexpected setpoint, the measured value can mislead a downstream code change about what the shield safely delivers |
| operator multimeter at socket VPP pin | the authoritative physical confirmation that >= 25V is actually present at the pin a chip would see — the firmware has no ceiling, so this is the only real safety boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-79-VPP | Damage (hardware) | shield VPP rail vs the 25V-declared NMOS chip | mitigate | Chip-OUT >= 25V multimeter dry-run (Task 2) is `autonomous: false` and ordered FIRST; the Plan 02 ceiling change is authorized ONLY on a CLEARED (>= 25V) verdict; live R1/R2 reconcile (Task 1) makes the firmware-mediated reading meaningful; firmware `eprom_check_vpp` +/- tolerance is the runtime backstop but is NOT a substitute for this gate |
| T-79-REV0 | Damage (hardware) | Modified Rev 0 shield as an untrustworthy VPP gate | accept/mitigate | Rev 0 is excluded by the standing bench rule (eprom_check_vpp warns rather than errors on REVISION_0); Task 1 requires the operator to confirm Rev 2.2 or Rev 2.0 silkscreen and STOPs on Rev 0 |
</threat_model>
