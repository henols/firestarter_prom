    same character rich.prompt.Prompt.ask uses to SEPARATE choices in the
    `[...]` display. So the prompt renders `[new/blank/pulled/used]` (looks like
    4 options) but only two exact strings are accepted; natural inputs `new`,
    `blank`, `pulled`, `used` are all rejected. Same class of friction on shield
    revision — a partial `2.0` is rejected; only the exact `Rev 2.0` is accepted.
    ROOT DESIGN DECISION (operator-approved this session) — the entire
    interactive provenance-collection model (RPT-04 / D-04 / D-05 / D-06) was
    descoped in 112-04. Rationale established with operator:
      * fw version + board identity are auto-capturable (threaded via AutoCapture).
      * hardware/shield revision IS queryable via HardwareManager; a COARSE bucket
        (REVISION_2_0 = 0x02 covers 2.0/2.1/2.2) or REVISION_UNKNOWN (0xFE) is
        good enough to auto-capture, no human prompt needed.
      * chip_origin is self-reported + unverifiable + largely REDUNDANT with the
        objective chip_id_expected/actual + mismatch reason AutoCapture records. Dropped.
      * owns_eraser is the weakest signal (only says a UV chip COULD be re-erased). Dropped.
      * pot_touched (the one genuinely-invisible voltage confounder) — FULL removal
        this session; a future `--pot-adjusted` flag is a possible later addition,
        explicitly out of scope now (do NOT re-introduce a prompt for it).
