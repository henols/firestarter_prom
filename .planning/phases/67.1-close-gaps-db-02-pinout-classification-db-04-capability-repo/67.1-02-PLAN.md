<objective>
Complete DB-04: surface the `support_status` taxonomy to the operator. (1) `firestarter info <non-supported-chip>` renders a status-specific support line from the DB's `support_status` + `unsupported_reason`; supported chips are unchanged. (2) `firestarter write/read/verify <non-supported-chip>` prints the status-specific reason verbatim (Plan 01 reworded the DB strings to be the authoritative message — Approach A) and exits non-zero before any serial byte; the 66-05 refusal guard already fires, the delta is making the message status-specific. (3) A per-status pytest CLI matrix asserts the status-specific text + exit code for all three non-supported statuses.

Purpose: Make the host honest about capability — operator sees WHY a chip is non-supported in both `info` and refused chip-ops.
Output: Updated `eprom_info.py` + `cli_handlers.py` + expanded `test_cli_handlers.py`, full CI gate green.
</objective>
