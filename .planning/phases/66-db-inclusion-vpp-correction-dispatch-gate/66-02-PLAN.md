<objective>
Rework `check_dispatch.py` so the dispatch/correctness gate treats non-`supported`
chips as legitimately non-dispatchable (DB-05 / D-10), and add the three
consistency assertions that keep the new `support_status` taxonomy honest. The
rework is forward-compatible: it must keep the gate green on the CURRENT 734-chip
DB (where no chip yet has a `support_status` key, so all default to `supported`),
and only changes behavior once Plan 03 regenerates the DB with the new field.

Purpose: Without this rework, the `not_implemented` FAIL bucket added in Phase 62
would FAIL the moment Plan 03 includes `protocol-not-implemented` chips (the very
chips that are SUPPOSED to route to not_implemented). D-10 inverts the logic:
not_implemented is a regression only for a chip claiming to be `supported`.

Output: edited `tools/check_dispatch.py` — reworked bucket + three new
consistency-assertion lists, all using the existing per-bucket FAIL idiom.
</objective>
