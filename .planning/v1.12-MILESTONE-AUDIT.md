# v1.12 Milestone Audit — Firmware Protocol Dispatch Hardening + Skeletons

**Audited:** 2026-06-15 · **Status:** ⚠ gaps_found · **Score:** 15/17 requirements satisfied

## Milestone Definition of Done

Make the whole stack honest about what it can and cannot program:
1. **Firmware fail-closed dispatch** — an explicit "not implemented" wire response the host surfaces cleanly, plus skeleton infeasibility markers.
2. **Capability-honest database** — *list* (not silently drop) DIP parallel chips RURP cannot fully support, flagged with a `support_status` taxonomy (`protocol-not-implemented` / `adapter-required` / `vpp-exceeds-max`) the host reports clearly.

Framework + honest reporting only; **no new chips become programmable**. Dual-repo lockstep wire change; provable on the native dispatch harness + host pytest (no bench required to close).

> **Scope note:** ROADMAP heads this milestone as "Phases 62–68," but Phase 69 (CLI Command-Surface Robustness Audit) was inserted after a live `info` crash and is execution-complete, while **Phases 67 and 68 were never planned or executed** (no phase directories). The two outstanding requirements (DB-02, DB-04) map to those two unexecuted phases.

- **Flow 1 — Firmware→host dispatch:** `configure_memory()` (memory.cpp:105-118, named arms + `protocol != 0` guard before the `mem_type` fallback) → `configure_not_implemented()` emits 0xBB with protocol value, NULL operation pointers, zero hardware side effects → host `expect_ack` decodes `response.id == 0xBB` (serial_comm.py:444-445) → raises `ProtocolNotImplementedError` → `map_typed_errors` prints "Unsupported protocol:" (subclass-first). **WIRED** (probe/connect intercept gap closed in 65-02.)
